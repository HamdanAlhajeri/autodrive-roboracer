# September 21 milestone

Build AVLite plugins for fast, repeatable autonomous racing. Develop in the
simulator, then transfer the sensor, mapping, localization and control interfaces
to the real car. Track evidence in the [checklist](checklist-2026-09-21.md).

## A. Fast, repeatable driving

Minimize clean lap time on the practice track while working toward **measured
5 m/s on suitable straights** and slowing before corners.

$$
\min \bar T_{\mathrm{lap}}
\quad\text{subject to zero collisions/resets and repeatable clean laps.}
$$

- Record actual/target speed, steering, throttle, clearance, sensor age and timing.
- Tune preview and corner speed using measured vehicle response.
- Preserve watchdogs, correct units and saved per-run settings.
- Screen each candidate with three clean laps; increase calibrated speed ceilings
  in 0.5 m/s steps. A configured ceiling is not evidence of reaching that speed.

**Acceptance:** three fresh runs of **ten consecutive clean laps each**, using
the same final profile and no manual intervention during measurement. Report
lap mean/variation, actual straight speed, interruptions and any remaining
limitation at 5 m/s. Retain failures alongside successful runs.

## B. Offline mapping and localization

Keep the established live simulator controller on ground-truth localization
while developing and evaluating the estimator separately.

- Record raw LiDAR, IMU, encoders, transforms, commands and reference poses with timestamps.
- Build a 2D occupancy grid from LiDAR and ground-truth poses initially; preserve
  free, occupied and unknown cells, resolution and frame metadata.
- Wrap AVLite's existing ICP with a saved reference map, one supplied initial
  pose, encoder/IMU prediction and explicit match-failure reporting.
- Use ground truth only for initialization/evaluation, never later estimator updates.
- Keep algorithm cores independent of ROS and expose AVLite strategy interfaces.

**Acceptance:** a saved map and repeatable localization evaluation on a separate
recording, with trajectory/error graphs, failure counts, processing times and
tests for transforms, invalid/missing sensors and replay. The existing LiDAR
outline and RaceMap do not complete occupancy mapping or localization.

## Scope and hardware extension

The practice track is required. A new `.obj` track remains optional pending the
file and a compatible Unity project. Opponents, loop closure and autonomous SLAM
are outside this milestone.

The 20 September hardware direction adds [Jetson plugin preparation](real-car-plugin-plan.md):
identify the car, reuse AVLite localization, and provide remote run/stop.
Hardware deployment and live estimated-localization driving have separate
acceptance checks; they do not count as completed simulator work.
